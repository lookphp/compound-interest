# 想实现复利人生？我用 WorkBuddy 打通复利的每一个环节

如果你也用 AI 写过东西，大概率踩过同一个坑：

**它写得很快。但你不知道它写的数对不对。**

我这两天用 WorkBuddy 把一本 2.6 万字的书从初稿做到可以公开：33 节、6 个部分、10 个算式、8 张图，外加 **61 项自动互检**和一条命令跑完的 **8 项校验**。书在 GitHub 上，每个数字都能按计算器复核。

这篇文章不聊“AI 真好用”。聊流程——以及为什么这套流程本身，恰好就是复利。

## 一、我原来卡在哪

写字的人都有两个隐疾，跟才华无关：

**第一，数字会漂。** 同一件事，第一稿写“27.3%”，第三稿写成“27%”，读者一算就觉得你在编。

**第二，结构会塌。** 补写一章，很容易粘到附录后面去——自己读没问题，因为你知道它该在哪；读者不知道，读者是按顺序读的。

这两件事人眼都查不出来。人眼擅长判断“顺不顺”，不擅长判断“对不对”。

所以我把判断“对不对”这件事，整个交给了工具。

## 二、五个环节，正好对上复利的五个条件

写这本书时我一直在用五个条件筛事情。做完才发现，**用工具的过程，本身就在满足这五条**。

| 环节 | 工具实际做的事 | 对应条件 |
| --- | --- | --- |
| 结构 | 目录、算式索引、图表索引都由脚本从正文提取，不手写 | ① 可累积 |
| 计算 | 所有数字进一个脚本，改一个参数全部重算 | ② 正期望、不归零 |
| 校验 | 一条命令跑 8 项校验，改完就跑 | ③ 足够轮次 |
| 成本 | 检查器是一次性投入，之后每轮几乎零成本 | ④ 边际成本不递增 |
| 存续 | 零依赖脚本 + 数据快照 + Git 仓库 | ⑤ 不折旧 |

逐条说人话。

**① 可累积**：手写的目录只能用一次，下次改章节就废了。脚本提取的目录，改一百次都自动跟着变。**同一份劳动被复用了，这才叫累积。**

**② 正期望、不归零**：这条是一票否决。一个数字错了，整本书的信任就归零——读者不会说“这段错了”，读者会说“这人不靠谱”。所以计算必须交给脚本，不交给记忆。

**③ 足够轮次**：人一天能认真复核几遍？两遍，第三遍开始骗自己。脚本一天能跑几十遍，而且不烦。**复利要的是轮次，人最有优势的不是算得快，是能一直算。**

**④ 边际成本不递增**：写第一个检查器花了力气，之后每次改稿都是顺带跑一下。第 100 次检查的成本，低于第 1 次。

**⑤ 不折旧**：脚本只用 Python 标准库，不装任何第三方包；数据是固定快照，不是实时接口。**理由是五年后它还得能跑。** 一个依赖三十个库的脚本，半年就是废铁。

## 三、两个真实的翻车现场

这部分才是这篇文章的重点——因为顺利的部分谁都会讲。

**翻车一：我把负债当资产加了。**

书里有一笔账：欠 1 万，五年后仍欠 7,270；同样 1 万投在年化 8% 的地方，五年后是 14,693。净资产差多少？

我原来写的是 21,963。**错。** 那是把两个数**相加**——等于把负债也当成资产算了一遍。正确的算法是相减：14,693 − 7,270 = **7,423**。

这个错是被人拿着计算器抓出来的。修完之后我做了一件更狠的事：**把这个错误口径永久写进脚本，标注“必须被拒”。**

现在每次跑校验，它都会把 21,963 打出来，然后告诉你：这是错的，正确的是 7,423。**留一个路标，比改一个数字有用。**

**翻车二：检查器自己有 bug。**

我给书稿加了一节编号 2.7，然后把检查器当成真相。它说“编号与结构一致”。

我做了个反向测试：把 2.7 故意改成 2.9，看它能不能抓住。结果它**还是**说一致。

因为它只校验了“3.1 的 3 属于第三部分”，没有校验“第二部分内部的节号必须从 1 连续到 N”。跳号它根本看不见。

修好之后，同一个测试终于报出：`第二部分的节号不连续: 1, 2, 3, 4, 5, 6, 9`。

这件事教给我一条规矩，比任何工具技巧都值钱：

> **新检查必须做反向测试，才算建立。**
> 一个没被故意喂过错误的检查器，你不知道它到底在检查什么。

## 四、为什么这是复利，而不是“效率提升”

效率提升是一次性的：这本书省了我两天，下一本书还是从零开始。

复利是：**检查器留下了，脚本留下了，书稿留下了。**

下一本书不用从零开始，从这套 8 项校验开始。第一本花在“建工具”上的时间，第二本是净赚的——这就是条件 ①“可累积”在起作用。

用一句话区分：

**效率提升让你这次更快，复利让你下次更省。**

前者是线性的，后者才是指数的。而决定它是哪一个的，不是工具多强，是**你的产出有没有变成下一次的输入**。

## 五、今晚就能开始的四步（不用会编程）

不需要会编程，也不需要一开始就搭全套。顺序是这样：

1. **先找出你反复在算的那三个数。** 报价、成本、转化率、复购——就是你每次写材料都要重算一遍、而且每次都可能算不一样的那几个。
2. **把它们收进同一个脚本。** 让数字只有一处出处，改参数就全部重算。这是全书最省力的一步，也是收益最大的一步。
3. **写一条“打脸命令”。** 一条命令把所有关键数字重跑一遍，对不上就报错。以后每次改稿，先跑它。
4. **故意喂它一个错。** 把某个数改错，看它能不能抓住。抓不住，说明你的检查器在装样子——这一步不能省。

**做完第四步，你才算真的有了一套检查，而不是有了一堆脚本。**

## 六、但有一个环节，工具帮不了你

书里我专门写了一节，讲五个条件之外还有一件事：

**这五条问的全是“你这一侧”**——你的成果在不在、你会不会归零、你有没有时间、你的成本、你停下来会怎样。五个主语都是“你”。

没有一条问：**有没有人来用。**

五条全勾，只证明“如果交换发生，它会复利”。**它从来没有证明交换会发生。**

工具能帮我把“我这一侧”做到 5/5：结构自动、数字可算、校验常跑、成本趋零、五年可跑。但它管不了另一侧——有没有人读到这儿，有没有人因为其中一条改变了下一次动作。

那一侧我控制不了。我能做的只有一件事：**把它放到你能拿到的地方。**
