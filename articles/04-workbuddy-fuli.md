# 想实现复利人生？我用 WorkBuddy 打通复利的每一个环节

![图1 封面](assets/04-cover.png)
<!-- 配图1 提示词见 04-image-prompts.md -->

写完一本书，要干多少活？

算数。查错。画图。管结构。盯排版。还得防着自己手滑改错。

这些活，我基本没干。

我负责想和挑错，剩下的，全交给 WorkBuddy——一个能读文件、跑命令、自己搭工具链的 AI 助手。不是只会聊天的那个对话框。

两天，它交给我一本 26,328 字的书：33 节、6 个部分、10 个算式、8 张图。每个数字都能按计算器复核。书稿和工具链，全在 GitHub 上。

这篇文章，就讲一件事：它是怎么替我干活的。以及，为什么这套干法，本身就是复利。

01
PART
它实际替我干了哪些活
TASKS

不讲概念。直接上单子。左边是我说的话，右边是它交出来的东西。

| 我下的指令 | 它交付的 |
| --- | --- |
| “把正文数字做成自动互检，别让人眼维护” | 一套互检脚本，从 17 项加到 61 项 |
| “帮我作图，加实际案例” | 8 张图，数据直接从书稿脚本取，数字一个不动 |
| “统计全书数字，逐个判断哪些是算出来的” | 173 处数字的普查清单，算错的全被它翻出来 |
| “补写某一节” | 新节 + 同步更新目录、索引、互检、README，一处不漏 |
| “继续” | 从上次停的地方接着干，不重复、不遗漏 |

最后一行，是我用下来最意外的。

它的记忆，不在聊天记录里。在仓库里。

每天我只要说一句“继续”，它先把自己上次写的记录和校验结果读一遍，再接着干。我出差一周回来，它还记得这本书——因为它是真的在翻文件，不是凭印象。

02
PART
最值钱的一单
BUG

书里有笔账。

欠 1 万，五年后还欠 7,270。同样 1 万，投在年化 8% 的地方，五年后是 14,693。净资产差多少？

我按计算器之前，写的是 21,963。

错。

那是把两个数加起来了——等于把欠的钱，也当资产算了一遍。对的是相减：14,693 − 7,270 = 7,423。

这个错，是我自己拿计算器按出来的。抓出来之后，我把它丢给 WorkBuddy。它干的不是“把数改掉”这么简单，是三件事：

1. 把正文里所有引用这个数的地方，全部改正；
2. 把这笔账收进计算脚本，从此只有一处出处；
3. 把 21,963 这个错误口径，永久写进校验，标注“必须被拒”。现在每次跑校验，它都会把这个数打出来，告诉你：这是错的。

第三件，最值钱。

改一个数字，错还会再犯。立一个路标，同类错误从此过不了门。

![图2 路标拦截](assets/04-gate.png)
<!-- 配图3 提示词见 04-image-prompts.md -->

后来，它自己的检查器也翻过一次车。

我故意把一节的编号改错，喂给它，它照样报“一切正常”。它自己找到那个洞，补上，还把一句话写进了工作规矩：新检查，必须故意喂错，才算建立。

03
PART
干活姿势：人管什么，它管什么
ROLES

这几天，我最确定的一件事，就是怎么分工。

这也是 WorkBuddy 这种“能动手的 AI”，和“只会写字的 AI”最大的区别。

- **人负责想和纠错。** 哪一节该补、数字对不对得上常识、这个故事该不该进书——机器判不了，只有人能判。
- **它负责执行和维护。** 算数、查结构、盯排版、更新索引——人眼擅长判断“顺不顺”，不擅长判断“对不对”。而“对不对”，恰好是它能一天查几十遍、还不嫌烦的部分。

用错姿势的人，是让 AI 写，然后自己一行行检查。又累，又靠不住。

对齐这个分工，活，就换了主人。

04
PART
为什么这算复利，不叫“效率提升”
COMPOUND

效率提升，是一次性的。这本书它省了我两天，下一本还是从零开始。

复利是：互检留下了，脚本留下了，规矩留下了。

![图4 复利曲线](assets/04-curve.png)
<!-- 配图4 提示词见 04-image-prompts.md -->

下一本书，不用从零开始。从这 61 项互检、8 项校验开始。第一本花在搭工具上的时间，第二本是净赚的。

一句话分清楚：效率提升让你这次更快，复利让你下次更省。

分水岭不在工具多强，在它的产出，有没有变成下一次的输入。

05
PART
你现在就能下的四句指令
TRY

照抄就行。不用会编程。这正是 WorkBuddy 这种“能写代码、能跑命令”的助手，才接得住的活。

1. **“找出我这份材料里，反复出现、每次都要手算的数字，列成清单。”** ——报价、成本、转化率，都算。
2. **“把这些算式收进一个脚本，让每个数只有一处出处，改参数全部重算。”** 它会顺手把你算错的抓出来。
3. **“建一条校验命令，一条指令重跑全部关键数字，对不上就报错。”** 以后每次改完，喊一声“跑校验”。
4. **“故意改错一个数，看校验能不能抓住。”** 抓不住就让它修，修完再试。这一步做完，你才真的有一套检查。

做完这四句，你的材料，就有了和我这本书一样的东西：数字只算一遍，错误活不过一条命令。

06
PART
但有一件事，它替我干不了
LIMIT

书里专门有一节，讲这个。

五个条件，问的全是“你这一侧”——成果在不在、会不会归零、成本高不高。这一侧，工具能全包掉。上面那张单子，就是证据。

但五个条件之外，还有一问，谁也替不了：**有没有人来用。**

我可以用 WorkBuddy，把一本书做到每个数字可复核。但“你真的会看吗”，它算不出来。

我能做的，只有把它，放到你能拿到的地方。

全书在这儿，免费，每个数字都能复现：
https://github.com/lookphp/compound-interest

///

写在最后
LAST

说回开头，我用 WorkBuddy，把一本讲复利的书做完了。

我的想法是，先别把这当成“AI 多神”的故事。它神不神，看你把什么交给它。

我更愿意你先做一件自己能控制的事：把“找出反复手算的数字、收进脚本、建一条报错命令”这几句，丢给你的 AI 试一轮。看它能不能接住。

会用 AI，不等于一定做成复利。但亲手试过，你至少能更具体地说出，下一次该把什么交出去，什么还得自己盯着。

至于有没有人看，工具决定不了。这个，得靠写的人，和看的人，一起回答。

如果你也在用 AI 干活，评论区说一句你卡在哪一步——**能自动化的部分，我的整套思路和脚本都在仓库里，让它照着给你搭一份。**
