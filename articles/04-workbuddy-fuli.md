# 想实现复利人生？我用 WorkBuddy 打通复利的每一个环节

写完一本书要干多少活？算数、查错、画图、管结构、盯排版、防自己手滑改错。

这些活我基本没干。我负责想法和纠错，剩下的交给 WorkBuddy。两天，交付是一本 26,328 字的书：33 节、6 个部分、10 个算式、8 张图，每个数字都能按计算器复核，书稿和工具链全部放在 GitHub 上。

这篇文章就讲一件事：**它是怎么替我干活的，以及为什么这套干法本身就是复利。**

## 一、它实际替我干了哪些活

不讲概念，列单子。左边是我说的话，右边是它交付的东西：

| 我下的指令 | 它交付的 |
| --- | --- |
| “把正文数字做成自动互检，不要人眼维护” | 一套互检脚本，从 17 项加到 61 项 |
| “帮我作图，加实际案例” | 8 张图，每张图的数据直接从书稿脚本里取，不改数字 |
| “统计全书数字，逐一判断哪些是算出来的” | 全书 173 处数字的普查清单，算错的全被它翻出来 |
| “补写某一节” | 新节 + 同步更新目录、索引、互检、README，一处不漏 |
| “继续” | 从上次停的地方接着干，不重复、不遗漏 |

最后一行是我用下来最意外的：**它的记忆不在聊天记录里，在仓库里。** 每天我只需要说“继续”，它先读一遍自己上次的记录和校验结果，再接着干。我出差一周回来，它还认识这本书。

## 二、最值钱的一单：它把我的错当成了路标

书里有一笔账：欠 1 万，五年后仍欠 7,270；同样 1 万投在年化 8% 的地方，五年后是 14,693。净资产差多少？

我按计算器之前写的是 21,963。**错。** 那是把两个数相加——等于把负债也当资产算了一遍。正确是相减：14,693 − 7,270 = **7,423**。

这个错是我自己拿着计算器按出来的。抓出来之后我把它交给 WorkBuddy，它干的不是“把数改掉”，而是三件事：

1. 把正文里所有引用这个数的地方全部改正；
2. 把这笔账收进计算脚本，从此只有一处出处；
3. **把 21,963 这个错误口径永久写进校验，标注“必须被拒”**——现在每次跑校验，它都会把这个数打出来，然后告诉你：这是错的。

第三件最值钱。改一个数字，错还会再犯；立一个路标，同类错误从此过不了门。

后来它自己的检查器也翻过一次车——我故意把一节的编号改错喂给它，它照样报“一切正常”。它自己找到了洞，补上，还把“新检查必须故意喂错才算建立”写进了工作规矩。

## 三、干活姿势：人负责什么，它负责什么

这是我这几天最确定的分工：

- **人负责想法和纠错。** 哪一节该补、数字对不对得上常识、这个故事该不该进书——机器判不了，只有人能判。
- **它负责执行和维护。** 算数、查结构、盯排版、更新索引——人眼擅长判断“顺不顺”，不擅长判断“对不对”，而“对不对”恰恰是它一天能查几十遍、还不烦的部分。

用错姿势的人，是让 AI 写、然后自己一行行检查——又累又靠不住。**对齐这个分工，活就换了主人。**

## 四、为什么这算复利，不是“效率提升”

效率提升是一次性的：这本书它帮我省了三天，下一本书还是从零开始。

复利是：**互检留下了，脚本留下了，工作规矩留下了。**

下一本书不用从零开始，从这 61 项互检和 8 项校验开始。第一本花在搭工具上的时间，第二本是净赚的。一句话区分：**效率提升让你这次更快，复利让你下次更省。**

分水岭不在工具多强，在**它的产出有没有变成下一次的输入**。

## 五、你现在就能下的四句指令

照抄就行，不用会编程：

1. **“找出我这份材料里反复出现、每次都要手算的数字，列成清单。”** ——报价、成本、转化率，都算。
2. **“把这些算式收进一个脚本，让每个数只有一处出处，改参数全部重算。”** 它会顺手把你算错的抓出来。
3. **“建一条校验命令，一条指令重跑全部关键数字，对不上就报错。”** 以后每次改完，喊一声“跑校验”。
4. **“故意改错一个数，看校验能不能抓住。”** 抓不住就让它修，修完再试——这一步做完，你才真的有一套检查。

做完这四句，你的材料就有了和我这本书一样的东西：**数字只算一遍、错误活不过一条命令。**
